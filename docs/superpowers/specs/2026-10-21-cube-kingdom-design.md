# 큐브 왕국 건축가 (가칭) — 설계 문서

작성일: 2026-10-21 · 상태: 사용자 승인(전 범위 한 번에 구현, subagent-driven-development)

## 1. 무엇을, 왜

6학년 2학기 수학 3단원 「공간과 입체」를 바탕으로 한 **3D 블록 쌓기 퍼즐 웹앱**이다. 보드게임 「우봉고 3D」의 규칙을 빌려 왔다. 블록 조각을 판 위에 빈틈없이 쌓아 목표 모양을 완성한다. 학생은 수업 뒤 혼자, 자기 기기로 한다.

- **왜 이 장르인가:** 조각을 돌리고 쌓아 모양을 맞추는 행동 자체가 단원의 공간 감각이다. 퀴즈 팝업으로 게임을 멈추지 않는다. 학습이 곧 이기는 방법이다(`Downloads\교육용게임_개발철칙.md` 철칙 1·3·4).
- **왜 진짜 게임처럼:** 학생이 "수업 자료"가 아니라 "게임"으로 느껴야 다시 찾는다. 그래서 시각 수준의 기준을 issamGPT AI Mart에 올라온 게임으로 삼는다. 판타지 일러스트 배경, 마스코트, 금색 버튼, 입체 글자 로고가 들어간다.
- **성공:** 학생이 조작에 헤매지 않고 퍼즐에 몰입한다. 연속 정답으로 더 어려운 단서에 도전하고 싶어 한다.

### 근거 성취기준 (2022 개정)
- **[6수03-10]** 쌓기나무로 만든 입체도형의 위, 앞, 옆에서 본 모양을 표현할 수 있고, 이러한 표현을 보고 입체도형의 모양을 추측할 수 있다. → 핵심. 단서 단계 ②~④가 그대로 이 표현들이다.
- **[6수03-09]** 쌓기나무로 만든 입체도형을 보고 사용된 쌓기나무의 개수를 구할 수 있다. → 보조. "위에서 본 모양 + 수" 단서로 다룬다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 태블릿·크롬북 터치와 교사 PC 마우스 모두에서 자연스럽게 조작된다.
- 연속 정답에 따라 난이도와 점수 배율이 오른다.
- 처음 접속하면 짧은 조작 안내가 나온다.
- 백엔드 없이 정적 파일만으로 돌아간다.

**비목표 (만들지 않음)**
- 교사 대시보드, 교사 참여 기능, 실시간 집계
- 멀티플레이, 계정, 로그인, 서버 랭킹
- 서버, DB, 외부 API 호출

**반목표 (기술적으로 돌아가도 이러면 실패)**
- 문제 팝업이 게임을 멈추거나, 틀렸다고 벌을 주는 구조
- 3D 블록이 배경 그림 위에 붙인 스티커처럼 떠 보이는 화면. 원근·시야각이 배경과 다르거나 조각이 어수선하게 흩어진 화면
- 막힌 학생이 빠져나갈 길이 없는 구조
- 「우봉고」 이름, 원작 조각 세트, 퍼즐 카드, 그림을 그대로 쓰는 것
- 학생 개인정보 수집. 이름 입력칸도 두지 않는다.
- 학교 저사양 크롬북에서 3D가 꺼지거나 끊기는 것

## 3. 대상과 사용 환경
- **학생:** 6학년. 수업 뒤 개별 활동이며 교사는 개입하지 않는다.
- **기기:** 학생은 크롬북·태블릿 **터치**가 주력이다. 교사가 시연하거나 확인할 때는 **PC 마우스**를 쓴다. 두 입력 모두 1급으로 지원한다.
- **화면:** 가로 16:10 무대 기준. 세로 화면이면 "가로로 돌려 주세요" 안내를 띄운다(제가 정한 것).

## 4. 게임 규칙

### 4.1 한 문제
- 판 위에 **목표 모양**이 있다. 목표 모양은 바닥판 위 2층 이하이고, 아래가 빈 칸(돌출부)이 없다.
- 학생은 **조각** 3~5개를 모두 써서 목표 칸을 정확히 빈틈없이 채운다.
- **정답 판정 (제가 정한 것):** 모든 조각을 판 위에 쓰고, 쌓은 모양이 아래가 빈 칸이 없으며, **지금 보이는 단서와 맞으면** 정답이다. 정해 둔 한 가지 칸 집합과 비교하지 않는다.
  - 단서 1·2·3(3D 모양, 위+수, 층별)은 모양이 하나로 정해지므로, 결과적으로 목표 칸 집합과 같아야 한다.
  - 단서 4(위·앞·옆)는 세 모양을 만족하는 입체가 여러 개일 수 있다. 세 모양이 모두 맞으면 정답으로 친다. 단서대로 쌓은 학생을 오답 처리하면 반목표("틀렸다고 벌 주기")가 되기 때문이다. 교육과정의 "표현을 보고 모양을 추측한다"와도 맞는다. 조각 칸 수가 정해져 있으므로 맞는 모양의 범위는 그만큼 좁아진다.
  - "쉬운 단서 보기"로 단서가 바뀌면, 판정 기준도 바뀐 단서를 따른다. 단서들은 모두 원래 목표 모양에서 만든다.
- 조각은 위에서 떨어뜨리듯 놓인다. 이미 놓인 블록 위에 올라탈 수 있다. 그래서 놓는 순서도 퍼즐의 일부다.

### 4.2 문제 만들기: 거꾸로 만들기
1. 목표 모양을 먼저 만든다.
2. 그 모양을 4칸짜리 조각(일부 3·5칸 허용)으로 쪼갠다.
3. 쪼갠 결과는 반드시 풀리는 문제가 된다.
4. **해답 탐색기(solver)**로 해답 개수와 "놓는 순서 제약"을 세어 난이도를 매긴다. 해답이 적을수록, 순서 제약이 많을수록 어렵다.
5. 개발 단계에서 미리 생성해 **단계별 문제 은행 JSON**으로 앱에 넣는다. 런타임 생성은 하지 않는다(제가 정한 것: 품질 통제와 저사양 기기 부담 때문).
   - 단계마다 조각 수와 크기가 다르므로 은행은 단계별로 따로 둔다.
   - 자동 필터: 풀림 여부, 아래 빈 칸 없음, 판이 작업대 안에 들어가는 크기, 조각 모양 중복 과다 여부
   - 검수: 구현 측(Claude)이 문제 미리보기 한 장짜리 그림(contact sheet)으로 거른다. 사용자는 최종 표본만 확인한다.
6. 조각의 시작 방향은 무작위로 돌려 정답 방향과 다르게 둔다. 단, 항상 **가장 낮게 눕힌 방향**으로 시작한다.

### 4.3 난이도 사다리 (연속 정답으로 오름)
같은 문제라도 **목표를 보여 주는 단서 방식**이 바뀌면 난이도가 오른다. 단서 방식 하나하나가 단원 개념이다.

| 단계 | 단서 방식 | 개념 |
|---|---|---|
| 1 | 3D 모양: 판 위에 빛나는 하늘색 반투명 블록 | 따라 만들기 |
| 2 | 위에서 본 모양 + 칸마다 쌓인 개수 | [6수03-09] |
| 3 | 층별 평면도(1층·2층) | 층별 표현 |
| 4 | 위·앞·옆에서 본 모양 3장 | [6수03-10] 추측 |

- 단계가 오를 때 조각 수와 목표 크기도 함께 늘린다. 정확한 곡선은 구현자에게 맡긴다. 기준값: 1~2단계는 조각 3개, 3단계는 4개, 4단계는 4~5개.
- **판:** 판의 크림색 칸은 목표의 바닥 모양(위에서 본 모양)과 같다. 위에서 본 모양은 모든 단서에 이미 들어 있으므로 판이 이를 드러내도 정보가 새지 않는다(제가 정한 것). 목표 바닥은 ㄱ자처럼 직사각형이 아니어도 된다.
- **단계와 연속은 따로 움직인다 (제가 정한 것)**
  - 단계: 현재 단계에서 쉬운 단서 없이 2문제를 연달아 맞히면 다음 단계로 오른다. 최고는 4단계다.
  - 쉬운 단서로 푼 문제: 연속 기록은 이어지지만 승급 카운트는 0이 된다.
  - 건너뛰기: 연속 기록이 1 내려간다(최소 0). 승급 카운트는 0이 되고, 단계는 그대로다.
  - 단계가 올라도 연속 기록과 배율은 이어진다.

### 4.4 점수
- 한 문제 점수 = (기본 100 + 빠르기 보너스 max(0, 60 − 걸린 초)) × 연속 배율
- 연속 배율(제가 정한 것, 시안 "4연속 ×2"와 일치): 1~2연속 ×1, 3연속 ×1.5, 4~5연속 ×2, 6연속 이상 ×3

### 4.5 잘못 놓았을 때 · 막혔을 때 (사용자 확정)
- **오류 알림, 감점 없음.** 맞힐 때까지 그대로 두고, 시간이 가면서 빠르기 보너스만 준다.
- **다 올렸는데 다를 때:** 조각을 모두 판 위에 올렸는데 정답이 아니면, 판을 살짝 흔들고 "모양이 조금 달라요" 말풍선을 띄운다. 어디가 틀렸는지는 알려 주지 않는다.
- **60초 뒤 "쉬운 단서 보기":** 단서 카드에 버튼이 나타난다. 누르면 이번 문제만 한 단계 쉬운 단서로 바뀌고 이번 문제 점수는 절반이 된다. 1단계에서는 버튼이 나오지 않는다.
- **건너뛰기:** 언제든 누를 수 있다. 점수는 없고 연속 기록이 한 단계 내려간다(0이 되지 않음).

### 4.6 섬 성장 (보조 보상)
- 푼 문제 수에 따라 "내 섬"이 빈 섬, 블록 오두막, 블록 마을, 블록 성의 4단계로 자란다.
- 게임 화면에서는 **왼쪽 위 작은 배지**(썸네일, 다음 단계까지 남은 문제 수, 진행 바)로만 보인다. 사용자 지적으로 큰 패널은 폐기했다.
- 섬이 자라는 장면은 정답 연출 화면에서 크게 보여 준다.
- 단계 기준은 구현자가 정한다. 시안 기준값은 5문제마다 1단계.

### 4.7 저장 (기기 안에만)
`localStorage`에 다음만 저장한다.
- 최고 점수
- 섬 단계와 누적 정답 수
- 조작 안내를 다시 보지 않기 여부

모든 읽기·쓰기는 try/catch로 감싼다. 저장이 안 되는 환경에서도 게임은 돌아가야 한다.

### 게임 화면 배치
- **위쪽 왼쪽:** 단계 칩, 연속 칩, 그 아래 섬 배지
- **위쪽 가운데:** 미션 문구("이 모양을 똑같이 쌓아요!")
- **위쪽 오른쪽:** 점수, 그 아래 단서 카드
- **단서 카드:** 위·앞·옆 단서는 교과서식 배치를 쓴다. 위에서 본 모양 아래에 앞, 앞의 오른쪽에 옆을 놓는다. 블록 칸은 카드 너비 안에서 충분히 크게 그린다(사용자 지적으로 확대).
- **오른쪽 아래 도구:** 처음 시점 / 다시 놓기 / 건너뛰기 / 도움말
- **조각 회전 버튼:** 조각을 탭하거나 클릭하면 조각 둘레에 금색 원형 버튼 3개(돌리기·세우기·뒤집기)가 나온다.

## 6. 조작 (사용자 확정: 자유 3D 회전 계열, 단 회전판 방식)

| 동작 | 터치 | 마우스 |
|---|---|---|
| 조각 옮기기 | 조각을 끌기 | 왼쪽 버튼으로 끌기 |
| 조각 돌리기 | 조각을 톡 누르거나 길게 누르기 → 버튼 3개 | 조각 클릭 → 버튼 3개 |
| 화면 돌리기 | 빈 곳을 한 손가락으로 끌기, 또는 두 손가락 | 빈 곳을 끌기 |
| 원래대로 | "처음 시점" 버튼 | 같음 |

- 8px 이상 움직여야 끌기로 본다. 그보다 적으면 탭이다.
- **확대·축소는 없다.** 확대하면 3D와 배경 그림의 비율이 어긋난다(제가 정한 것).
- 조각은 격자에 자석처럼 붙고, 놓을 때 살짝 튕기는 효과가 있다.

## 7. 3D 연출 (사용자 지적 반영 사항, 가장 중요)

v2·v3 시안에서 사용자가 지적한 "스티커처럼 떠 보임", "시야각이 다름", "어수선함", "허전함"을 해결한 방식이다. v4 시안에서 확인했다.

1. **배경 그림은 그대로 둔다.** 작업실 그림(`game-bg-v4.png`)에 원형 작업대가 가운데에 있고, 높은 시점에서 내려다본다. 주변 소품이 풍성해 허전하지 않다.
2. **카메라를 그림에 맞춘다.** 그림 속 작업대 금테 안쪽 타원을 픽셀로 잰 값은 이미지 1344×768 기준으로 중심 (672, 418), 가로 반지름 440, 세로 반지름 250이다. 3D 작업대(반지름 6)를 투영한 타원의 위·아래·좌우 끝이 이 타원에 맞도록 카메라의 각도·거리·화면 오프셋을 반복 보정한다. 화면 크기가 바뀔 때마다 다시 맞춘다(`background-size: cover` 기준). 화각은 22°로 좁게 잡아 그림처럼 원근 왜곡을 줄인다.
3. **회전판 방식:** 화면을 돌리면 카메라는 고정되고 판과 조각을 담은 그룹이 Y축으로 돈다. 그래서 시야각이 배경과 영원히 일치한다.
4. **그림자:** 투명한 그림자 전용 바닥에 그림자만 떨어뜨린다. 빛 방향은 그림처럼 오른쪽 위다.
5. **판은 항상 작업대 정중앙**에 둔다. 보라 틀, 금테, 크림색 칸으로 만들고, 판 앞쪽에 "앞" 표시를 둔다.
6. **조각:** 쌓기나무 크기는 0.995, 모서리 둥글기는 0.05로 해서 틈이 거의 보이지 않게 한다. 받침대는 없다(사용자 지적으로 삭제).
7. **시작 배치:** 판의 왼쪽·앞·오른쪽(조각이 더 많으면 그 사이 각도)에 가지런히 놓는다. 판과 판 둘레 1칸, 다른 조각과 겹치지 않으면서 작업대 안에 온전히 들어가는 칸 가운데 목표 지점에 가장 가까운 곳을 고른다. 긴 조각은 판과 나란한 방향으로 놓는다.
8. **경계:** 조각의 모든 칸 모서리가 작업대 원 안에 있어야 한다. 끌거나 돌릴 때도 밖으로 나가지 않는다. 경계선은 따로 그리지 않고, 그림 속 금테가 곧 경계다.
9. **목표 모양(단서 1):** 하늘색으로 빛나는 반투명 블록이 은은하게 깜빡인다.

## 9. 기술 (제가 정한 것)
- **정적 웹앱:** HTML + CSS + ES 모듈, three.js r160(`RoundedBoxGeometry` 사용). **빌드 도구는 쓰지 않는다.** 한글 경로에서 vite 빌드가 깨지는 알려진 문제를 피하기 위해서다. three.js는 CDN 대신 저장소에 내려받아 넣는다(학교망 차단 대비).
- **배포:** GitHub Pages(989-alt 계정, 기존 퀴즈 게임과 같은 방식). 저장소 이름과 주소는 이름이 정해지면 정한다.
- **저사양 대응**
  - 기본: 그림자 맵 1024, 픽셀 비율 최대 1.75, `MeshStandardMaterial`
  - 프레임이 떨어지면 그림자를 끄고 픽셀 비율을 1로 낮추는 저사양 모드로 자동 전환한다.
  - WebGL을 만들 수 없으면 안내 문구를 띄운다.
  - (시안 작업 중 이 PC의 크롬이 3D 화면을 한 번 차단한 일이 있었다. 이 대응이 필요한 이유다.)
- **구조(권장):**
  - 문제 데이터와 해답 탐색기: three.js와 무관한 순수 JS
  - 게임 상태: 점수, 연속, 단계, 저장
  - 3D 장면: 보정, 회전판, 조각, 입력
  - 화면 UI
  - 순수 JS 부분은 단위 테스트한다.

## 10. 검증
- **단위 테스트:** 정답 판정, 떨어뜨리기, 회전 정규화, 경계 판정, 시작 배치(판·다른 조각과 겹치지 않음), 점수 계산, 문제 은행 전 문항의 풀림 여부(해답 탐색기)
- **화면 검증:** 헤드리스 Edge(Playwright `channel="msedge"`)로 캡처한다.
  - 투영한 작업대 타원과 그림 속 금테 타원의 오차가 작아야 한다.
  - 시작 배치에서 조각이 판을 가리지 않아야 한다.
  - 끌기 테스트에서 조각이 경계 안에 머물러야 한다.
- **실기기:** 학교 크롬북·태블릿에서 터치 조작과 프레임을 확인한다. 사용자가 수업 중일 때는 브라우저·PowerPoint 자동화를 하지 않는다.
- **학생 검증:** 철칙 II처럼 행동으로 잰다. 재방문 측정을 위해 링크를 미리 뿌리지 않는다.
